# ADR-0006: MCP para integração com sistemas externos

- **Status:** proposto (interface pronta; servidor MCP não implementado no prazo) · **Data:** 2026-10-06

## Contexto
O cenário menciona integrar dados externos via MCP. O agente depende de ERP, orçamento e cadastro de fornecedores.

## Decisão
- Toda leitura externa passa pela porta `ErpGateway` (somente leitura). Hoje ela é implementada por `MockErpGateway` (in-process).
- **Evolução planejada:** um servidor MCP `erp-mcp` expondo `get_cost_center_budget`, `get_supplier_profile`, `get_purchase_history` e `list_policies`, e uma implementação `McpErpGateway` (cliente MCP via Java SDK) selecionada por propriedade, **sem mudança no agente**.

## Trade-offs: MCP vs. skills/scripts internos
| | MCP | Integração interna |
|---|---|---|
| Reuso por outros agentes e ferramentas | ✅ Padrão aberto; um servidor serve vários agentes | ❌ Acoplado a este serviço |
| Governança | ✅ Allowlist de tools, autenticação e auditoria centralizadas no servidor | Dispersa |
| Latência | ❌ Hop extra (stdio/HTTP) | ✅ In-process |
| Operação | ❌ Mais um componente para versionar, monitorar e escalar | ✅ Simples |
| Segurança | ⚠️ Superfície nova (autenticação, escopo das tools, injeção via resultado de tool) | Menor |
| Testabilidade | Precisa de um servidor fake ou de contract tests | ✅ Mock direto |

**Recomendação:** MCP para sistemas **compartilhados entre agentes** (ERP, cadastro); integração interna para lógica **exclusiva do agente** (motor de regras, validador). Resultados de tool MCP devem ser tratados como dados não confiáveis (mesma delimitação de `<untrusted_input>`).

## Por que não foi implementado
O prazo de entrega era de 1 dia. Priorizamos o núcleo (contratos, grounding, guardrails, evals e observabilidade), que é avaliado de forma obrigatória. A porta `ErpGateway` já isola o ponto de troca.
